# 猫置物台、传送带与领养箱展示验证（2026-09-20）

版本保持 2.2.1；Forge 1.20.1 / NeoForge 1.21.1。使用说明见 `cat-depot-belt-adoption.md`。

## 覆盖范围

- 服务端新增 6 项：猫传送带原生链路创建、消耗、存档、掉落、选取及真实动力运输；置物台库存与存档、真实冲压/机械手/注液加工、碰撞体；普通/心愿领养箱输入展示同步与交易。
- 双端真实客户端：两种领养箱四方向、同一方块实体更换花色及清空；原生与猫传送带贴图区分；置物台模型和真实持有物渲染顶点高度（相对原生下移 1/16）；GPU 预览人工检查。
- 正常 build 包含饰品 API v3、词条 API v1、资源、饰品定义及发布隔离校验；测试源码、SDK 和预览不进入运行 JAR。
- 资源导出一致性与独立全局配置回归通过。

## 验证期间发现并处理的问题

- 新功能先后出现预期失败：缺少注册/猫饼显示、NeoForge 传送带起点组件读取、外观标记早返回导致的存档读取、猫传送带掉落、置物台高度。修复后对应服务端/客户端测试通过。
- 代码审查指出置物台物品应随模型下移 1 像素；已实现专用渲染器，并用真实物品顶点差值及 GPU 预览验证。碰撞体同步匹配 12 像素台面。
- 旧词条战斗测试曾得到 5.2 而非 4 伤害：固定属性仍有原生随机暴击，智力 30 对应 1.3 倍。仅在测试中设智力为 0，消除倍率而保留精确伤害断言；未改生产战斗逻辑。
- 旧警戒范围测试曾在 95 tick 超时，报告 `No sequences finished`。异步实体就绪后仍需完整 66 tick 行为检查，原总预算只留 29 tick 给加载。测试改为独立 100 tick 就绪上限、明确诊断、原有 22/44/66 tick 检查和 176 tick 总预算；未改警戒机制。未记录原失败时的实际就绪耗时，超时原因来自流程与框架错误路径分析。
- Forge 旧自动炮击测试在首轮及最终全量回归出现目标为空，中间一次原样通过；最终 `additions-full-clean.log` 还出现旧空中治疗 `selfAndAirbornePilot` 精确回血断言失败。最终全量为 124 项中 2 项失败，不能宣称 Forge 全量通过。这两项根因未完整确定，未修改其生产机制或断言；保留失败日志。本次功能另以 6 项独立服务端用例和真实客户端验证作为部署检查。
- 全量套件中的真实 proto-chunk promotion 为已有显式 opt-in 分支，本轮未启用；日志明确 SKIP，不计作该场景已验证。
