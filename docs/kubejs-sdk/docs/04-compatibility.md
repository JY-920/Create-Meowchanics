# 更新兼容、迁移与维护

## 可以保证的范围

同 Minecraft / KubeJS 兼容线内，本模组继续支持 API v3 与数据 schema 1 时，脚本不依赖 accessories.37 等内部构建号，正常更换 JAR 不需要改这些脚本。新版本增加 API 不应使旧版脚本失效。

新增 supportsApi(3) 是明确的兼容声明，不等同于 apiVersion()>=3。将来 apiVersion()=4 时，保留旧 v3 适配器并返回 true，现有脚本仍启用。旧 accessories.36 尚无 supportsApi，示例仅在 apiVersion()===3 时回退接受。

## 已加的工程约束

- 冻结 contracts/api-v3.json 对应的 84 个 Java 签名、15 个事件、六维字段、职业、机制键与 36 件保存用 ID。
- 正常 build / jar 检查这些条目不能无声消失或改类型；允许增加新成员。
- 不允许通过删旧快照或降低测试要求解决兼容失败；破坏性重构应保留旧入口委托新实现。
- 真实 MC 测试继续使用旧的 36 件脚本核对效果、装卸、存档和 /reload。ABI 检查只检查接口形状，不能代替行为回归。
- 存档持久状态用物品 handle，ID/状态键不随显示名、本体版本或美术变化。
- SDK 与玩家脚本不打进本体 JAR，更新 JAR 不覆盖用户 kubejs。

## 脚本的安全降级

laowu36_compat.js 先检查版本契约；laowu36_effects.js 在全部事件注册成功后才设置 ready。data 适配器通过 catalog.register 检查 ready 后才发出替换定义。

未知 API、schema 不兼容、缺 compat、缺 effects 或注册中途抛错时，当前加载周期不发出覆盖，让原生定义生效并提示日志。模拟了旧 API2、旧 API3、未来 API4 保留/不保留 v3、未知 schema、缺文件和部分注册失败。

降级保证的是“不主动用缺失的七项脚本覆盖掉原生效果”，不是保证新功能还在。任意损坏的 KubeJS、其他模组冲突、保存了陈旧虚拟数据的异常重载等仍应通过完整重启与日志确认。不要忽略警告后宣布自定义效果正常。

## 不能承诺的范围

- 跨 Minecraft / 加载器 / KubeJS 大版本，须选择对应 data 适配器并实际测试。
- 用户删除 startup 注册会使自定义物品 ID 缺失；删除事件文件却保留另一套旧数据可能让效果缺失。
- 第三方修改本体、反射内部类、直接操作映射后的原版方法或内部 NBT，不在契约内。
- 引擎机制的平衡数值与算法若调整，29 件声明式示例会调用更新后的引擎；接口兼容不意味着历史战斗平衡永远冻结。
- 未来的未知代码无法现在测试；本包不把兼容声明当作无限保证。

## 升级顺序

1. 备份模组、kubejs 和存档；新物品 startup ID 不改。
2. 本体同线更新只换 JAR，保留脚本；确认启动日志与兼容声明。
3. 测试猫装备、卸下、职业条件、一次成功触发、取消、冷却、猫饼恢复、/reload。
4. 若升级 SDK，替换同一加载器的四文件整套，不混旧版。
5. 有永久 setStatBonus 自定义状态时，先做迁移清理再卸载机制；本包 36 件替换没有此类永久加成写入。
6. 失败时停止升级，回退完整备份或移走整套替换文件恢复原生；不要删除原有物品或存档“修复”报错。
