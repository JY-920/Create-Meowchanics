# 耄耋 Boss 首版设计

状态：用户已于 2026-10-06 确认设计，实施计划待审阅。目标是交付可玩的 Forge 1.20.1 与 NeoForge 1.21.1 原型，有无机械动力均可使用。玩家连续抚摸博古架上的猫三次，触发巨型 Boss 战；正常击败或脱战后还原原猫，保留养成数据。

首版采用中等难度，重点验证召唤演出、招式预警、反击窗口和原猫还原。暂不制作完整四招组合系统、独立美术模型、专属装备或新战利品。

## 触发与变身

普通空手右键保留现有半秒哈气。蹲下空手主手右键架上的猫才算抚摸，旁观者和持有物品的交互不计数。次数按猫累计，间隔至少十个游戏刻，八秒未继续则清零，防止双手事件和连点重复计数。

每次有效抚摸只触发现有半秒哈气，不增加躲头、拍尾、压耳动画、次数提示或其他表现。第三次哈气同时检查召唤位置：在博古架附近已加载区域寻找有支撑、无流体危险、符合世界边界且容纳完整 Boss 碰撞箱的落点。找不到则提示腾出空间，保持原猫和架子，不消耗最后一次触发机会。

位置检查成功后先进入三秒气场召唤，猫仍留在博古架展示位。淡金色气流沿博古架外缘环绕并螺旋上升，由疏到密、由慢到快，结束时收束到猫身上并向外散开。特效按架子的世界位置和朝向定位，围绕整座架子而非只围绕猫；不用遮挡主体的高密度光柱，不强制切镜头。

气场结束后再次核对落点与源猫状态，成功后猫离架，在安全落点用一秒完成平滑巨大化，随后显示“耄耋·不许摸”血条并开始战斗。整体演出约四秒。首版使用现有巨猫模型和四倍体型，实际实体宽两格、高三格；沿用原猫材质。不显示旧巨猫零食的悬浮召唤道具。后续再根据实机效果决定是否提高体型、调整头肩比例或制作橘猫专属外观。

召唤期间不接受重复抚摸触发。架子被拆、猫离开展示位或被驯服、源区块卸载、最终落点被堵住时取消召唤，保留原猫；不生成额外 Boss，也不留下持续气场。最终快照以变身提交时的原猫数据为准，避免气场期间的正常交互造成数据回退。

原猫进入挑战后的五分钟冷却写入其持久数据，普通右键哈气不受影响。召唤过程不修改玩家建筑，不强制切镜头，不加载未加载区块。

## 首版战斗

初始平衡目标为三百生命值，适合使用普通战斗装备学习招式；不改变现有巨猫 Boss 的八百生命值和旧召唤方式。所有伤害、命中和阶段转换由服务端决定，客户端仅渲染同步姿势与预警。

首版招式包括有蓄力的巨猫翻滚、跳跃砸地和新增扇形哈气。翻滚与跳砸复用现有碰撞感知移动和动画，哈气具有吸气预警、固定出招方向与恢复时间。玩家可以绕到侧后方躲避，哈气不穿过墙壁，也不在持续期间瞬间追踪目标。

普通近身攻击、翻滚、跳砸与哈气的初始伤害目标分别为六、八、十二和四点。连续攻击同一对象受招式命中冷却约束，不能每刻重复伤害。招式之间保留至少一秒反击窗口；战斗数据只用于首版调试，不作为最终平衡承诺。

半血后进入强化阶段，发出一次可识别的音效与粒子变化，缩短招式之间的休息，但不提高转向到瞬间锁定，也不取消蓄力和恢复。原概念里的双招组合、独立落爪冲击波和扑空抚摸弱点暂留到后续版本。

默认攻击对象为附近可战斗的生存或冒险玩家，不主动伤害普通猫和宠物猫。创造与旁观玩家不计入有效战斗参与者。召唤者附近无有效玩家时保留出场展示，连续二十秒没有有效玩家则结束挑战。

## 原猫数据与结束规则

新挑战采用独立的耄耋身份标志和源猫快照，复用现有巨猫实体底层。旧零食召唤的巨猫 Boss 保持旧行为，不自动还原，不改变已有存档语义。

源猫快照保留 UUID、名字、材质、年龄、驯服信息、六维属性、词条、套装、饰品及其持久脚本状态。博古架临时坐姿不写入原猫的正常坐下指令。原猫的短暂哈气和查看状态不延续到还原后。原猫养成效果不直接驱动 Boss 的战斗平衡。

变身必须先准备完整快照并成功加入 Boss，再移除原猫；任何失败保留原猫。Boss 保存快照、挑战身份与结束状态，退出重进不丢猫。还原前检查原 UUID 是否已经存在，避免重复生成。

正常击败和二十秒脱战都结束挑战。服务端将原猫恢复到有支撑、无碰撞的安全位置，再清除挑战实体和血条；没有安全位置时暂停挑战并保留快照，等待能够安全还原，不能直接删除数据。还原猫保持原名字和养成信息，不因 Boss 生命值归零而死亡。

首版不发放旧巨猫 Boss 的死亡掉落和经验，避免变身战斗错误触发旧奖励；没有新战利品也不会影响验证战斗本身。命令杀死挑战实体按结束挑战处理，正常卸载区块不触发还原。任意外部模组强行丢弃实体不在首版可保证的恢复路径内。

## 实现边界

博古架座位只负责抚摸计数与请求挑战，不承担 Boss AI。挑战生命周期由独立服务负责气场召唤计时、快照、召唤位置、结束与还原。气场计时以服务端为准，客户端按同步的锚点、朝向和进度播放限量粒子。现有巨猫实体通过耄耋标志进入专属数值、哈气与半血强化分支，普通巨猫路径保持兼容。

客户端渲染复用现有巨猫模型、骨骼与动画采样，耄耋专属巨大化与哈气动画只在挑战身份启用。Forge 与 NeoForge 保持相同玩法，平台差异只限事件、数据接口和注册适配。不改饰品 API v1–v3、词条 API v1 或已有物品 ID。

## 验收与部署

先用测试证明目前三次抚摸不会触发挑战，再实现。实际双端 GameTest 验证主手计数、每次半秒哈气、计数超时、普通右键不召唤、第三次开始气场但不立即进入战斗、气场结束才提交变身、召唤中重复触发与取消、障碍拒绝、召唤事务、存读档、原猫完整数据、正常击败和脱战还原、重复还原防护，以及旧巨猫行为不变。

战斗测试覆盖哈气预警与命中窗口、墙体遮挡、同目标命中冷却、半血转换和 NoAI 停止伤害。客户端实际启动并截图核对四种水平朝向的架子气场、原猫仍在架上的召唤过程、巨大化、血条、三种攻击与战后原猫，不把编译成功当作视觉通过。

执行双端正常 build、现有顶层 Node 回归和真实 KubeJS 饰品与词条回归。检查正式包无测试载荷后，按工程部署约定检查游戏进程，备份旧包并部署两个 Java 测试实例；不修改网易工程，不自动提交、推送或公开发布。
