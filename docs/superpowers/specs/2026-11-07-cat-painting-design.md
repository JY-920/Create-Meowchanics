# 猫画编辑桌与联机猫画设计

状态：用户于 2026-11-07 批准本设计及所列默认值，已开始在现有 develop 工作树中直接实施和验证。目标版本沿用当前双端工程，公开版本号不在本功能中变更。

## 已确认的需求

猫画编辑桌先沿用 create:schematic_table 的方块模型，界面使用同款 Create 风格，尽量复用素材和控件。放入猫画后可选择本地 PNG、JPG 图片，设置原生或像素模式、画面尺寸、宽度保留或高度保留裁剪，并印制成能像原版画一样挂墙的猫画。

猫画物品图标使用用户提供的 C:/Users/16611/Downloads/painting.png。挂墙实体的边框使用猫机壳的配色和纹理风格，不沿用原版画的棕色木框。

用户已确认联机其他玩家应能自动看到画作，并选择图片随世界保存、由服务器同步的方案。仅上传在桌内选中并确认印制的图片；本地原图删除后，已制作的画仍有效。

## 方案选择

采用世界内图片库与按内容去重的存储方式。服务器保存处理后的图片，物品和实体只保存图片编号及画作参数；客户端按需下载并缓存，不要求其他玩家手动安装资源包。备份或迁移世界目录时同时携带图片库。

未采用外部图片网址：需要外部服务，图片可能失效，也会额外暴露连接信息。未采用把图片字节直接塞入物品或实体数据：容易放大物品同步、存档及实体加载的数据量。这些替代方案均不作为本版功能。

## 提议的默认范围

以下默认值由实现方提出，已随本文档获得用户确认。

- 双端同时交付：Forge 1.20.1 与 NeoForge 1.21.1。
- 本版编辑桌依赖 Create，仅在安装 Create 时注册；猫画物品、挂墙实体、图片库和下载显示不依赖 Create，未安装 Create 时仍能显示和重新放置已有画作。
- 画作宽、高分别为 1–8 个方块的整数，默认 1×1。画框包含在配置的总占位内，不额外侵占邻格。
- 像素模式按每格 16×16 像素生成，最近邻显示，不做未经约定的调色板量化。原生模式使用平滑缩放，最长边至多 2048 像素，不宣称无损保留无限分辨率原图。
- 本版从创造物品栏取得编辑桌和空白猫画，配方作为后续独立调整，不擅自消耗猫毛、猫锭等额外材料。
- 不新增外网图片下载、动画 GIF、视频、文字绘制或自由拖动裁剪区域。

## 图片目录与编辑流程

本地导入目录为当前客户端游戏目录下的 cat_paintings/imports，采用蓝图桌同类的打开目录、刷新列表和选择操作。只列出该目录直接包含的 .png、.jpg、.jpeg 文件，大小写不敏感；不递归扫描其他目录，不上传文件名中的本机绝对路径，不跟随指向目录外的符号链接。

玩家将文件复制到导入目录，在编辑桌中选择图片后，客户端显示本地预览。此时不上传图片。切换模式、尺寸或裁剪方式会更新预览；损坏图片或超限图片显示明确错误，不影响画作物品。

编辑桌设一个猫画处理槽和确认按钮，不自动从背包取料。槽只接受一个空白或已印制猫画，拒绝其他物品。确认前可返回而不修改物品；确认印制后在原槽中转换这一个猫画，成功才写入新图像编号与参数。允许重印已有猫画，不额外收取材料；失败保留旧画。

上传期间锁定本次槽位事务，进度可见，不允许拿走后又凭上传回包凭空生成物品。关闭界面、离线、离开可交互距离、桌子破坏或槽位异常均取消提交并解锁，物品按正常容器规则留存或掉落。服务器只接受正在操作该编辑桌且满足距离、权限、槽位一致性检查的印制请求。

## 缩放与裁剪的准确含义

预览与最终生成使用同一变换，不拉伸图片；裁剪或留边都以中心对齐。

- 宽度保留：原图横向内容完整保留，按输出宽度等比缩放。高度超出画布时裁掉上下部分；高度不足时上下留画布底色。
- 高度保留：原图纵向内容完整保留，按输出高度等比缩放。宽度超出画布时裁掉左右部分；宽度不足时左右留画布底色。

例如 2:1 横图制作成 1:1 画：宽度保留会产生上下留边，高度保留会裁掉左右内容。不存在既完全保留指定轴、又始终铺满任意宽高比且不拉伸的处理方式，因此界面必须把预览和留边行为表达清楚。

画布底色为不透明浅米白。PNG 透明区域合成到画布底色；JPG 不透明区域正常保留。两种模式的几何裁剪一致，区别仅在输出清晰度与采样方式。屏幕预览应明确显示世界中的宽高比例和猫机壳式画框。

## 方块和界面复用

编辑桌方块建议 ID 为 laowu:cat_painting_table，沿用蓝图桌体积、水平朝向及模型结构，不改变 create:schematic_table 本身。猫画物品和实体建议 ID 为 laowu:cat_painting。新增注册项不得更改已有 ID。

Create 专用类放入现有 compat/create 或 create 隔离区域。使用蓝图桌背景、Create 选择框、按钮、槽位和玩家背包风格；必要时扩大内容区容纳预览与设置，但不把按钮压到输入框上，不显示无作用的蓝图上传控件。不直接继承含私有蓝图状态的屏幕后再遮盖旧控件。

图标、模型及纹理优先复用现有资源。外部素材的复制或引用需按其实际许可保留必要署名；猫画边框从本模组现有猫机壳素材取得，无 Create 显示时不能依赖 create 命名空间的纹理。预览和实体边框一致，使用固定像素宽度的纹理切片平铺，避免大尺寸画框被拉糊。

## 画作数据与世界保存

建议条目 schema 1：图像 SHA-256、宽格数、高格数、原生或像素模式、保留轴、印制者 UUID、数据版本。物品不存绝对文件路径或整张图片。以处理后标准 PNG 字节的哈希作为资产编号，同图同处理结果可复用，参数仍随物品和实体保存。

服务端图片库位于世界根目录 laowu/cat_paintings，路径只由服务端生成的哈希组成。写入使用临时文件与原子替换；先完成资产验证和持久化，再确认物品转换。失败不会留下引用不存在资产的成品。世界索引记录资产大小、尺寸、上传归属等信息，并在世界关闭时收尾。

不在本版自动删除未引用图片，以免背包、离线玩家或未加载区块的画作误丢图。管理员可查看磁盘占用；清理工具另行设计。仅复制一个画作物品到其他世界不会携带图片库，目标世界缺图时显示猫画占位图和缺图说明，不崩溃、不尝试读取本机路径。

## 联机传输与资源限制

沿用 Forge ModNetwork 通道和 NeoForge 对应 payload 注册，在各版本边界实现等价协议，不引入外部服务。图像解码、缩放、哈希和磁盘操作不占用世界 tick 或渲染主线程；上传数据先由客户端处理，再由服务端独立校验。

建议默认限制：本地源文件最多 16 MiB，解码前检查图片头；原图最长边不超过 8192 且总像素不超过 1600 万。最终纹理最多 2048×2048、上传编码后最多 8 MiB。服务端不接受客户端声称的尺寸或哈希为可信事实，必须验证实际 PNG 头、解码像素及内容哈希，丢弃元数据。失败清理缓冲和临时文件。

应用层每块数据不超过 24 KiB，使用会话编号、总大小、偏移和确认包，限制同时进行的会话数和传输速率；不能绕过菜单事务直接提交任意世界文件。默认每玩家一次并发上传、每分钟至多四次印制提交，空闲会话 30 秒超时。默认世界图片库限 1 GiB，可由服务器配置；已有资产仍可读取，达到上限时拒绝新增而不删除旧画。客户端磁盘缓存默认最多 256 MiB，GPU 缓存最多 64 MiB，均按最近使用淘汰，且切服后按世界命名空间隔离。

其他玩家在开始追踪挂墙实体或首次需要绘制相关物品时按需请求图片，服务端验证该玩家确实能访问所请求的画作再分块发送。未下载时显示占位图和加载状态；传输失败允许限速重试，不可每帧重复请求。重复哈希不重复传输。服务端不向客户端索取或提供任意文件路径。

## 挂墙实体和交互

采用原版画同类的 HangingEntity 支撑、碰撞和放置判定，但使用自己的尺寸和渲染器。仅允许挂在水平四个朝向的墙壁面，不挂地面或天花板。

服务器检查全部宽高覆盖区域的墙体支撑、空间冲突、世界边界、已加载区块及玩家操作权限。墙面不足或已有挂画冲突时放置失败，生存模式不扣物品；成功才消耗一个猫画，创造模式不消耗。偶数宽高按原版画的居中规则定位。

拆除、支撑破坏和爆炸依原版画的伤害及掉落规则处理；允许掉落时保留图像编号和所有画作参数，不重复掉落。空白猫画不能当作已印制成品挂墙，给出使用编辑桌的提示。实体保存并同步编号与尺寸，画框正面、侧面和背板使用猫机壳式外观，画面不闪烁、不与墙面重叠。
